# cPanel Deployment Guide

## Problem Solved

This document explains the fix for the 404 asset errors when deploying the Breakdown Guide frontend to cPanel hosting.

### Original Issue
- Built application showed blank page on cPanel
- Browser console showed 404 errors for all assets:
  - `/assets/index-*.js` (404)
  - `/assets/vendor-*.js` (404)
  - `/assets/supabase-*.js` (404)
  - `/assets/index-*.css` (404)

### Root Cause
Vite by default generates **absolute paths** (starting with `/`) for all assets. This works fine when deployed to the root of a domain, but fails on cPanel when:
- The app is in a subdirectory
- The server doesn't properly resolve absolute paths
- The .htaccess rewrite rules don't handle absolute asset paths correctly

### Solution
Added `base: './'` to `vite.config.js` to generate **relative paths** (starting with `./`) for all assets.

## Configuration Changes

### 1. vite.config.js
```javascript
export default defineConfig({
  plugins: [react()],
  base: './', // Use relative paths for assets - critical for cPanel deployment
  // ... rest of config
})
```

### 2. index.html (source)
Changed favicon path from absolute to relative:
```html
<!-- Before -->
<link rel="icon" type="image/svg+xml" href="/logo.svg" />

<!-- After -->
<link rel="icon" type="image/svg+xml" href="./logo.svg" />
```

## Deployment Steps

### 1. Build the Application
```bash
cd /Users/anthony/Go\ BARRY\ App/BreakdownGuideapp/frontend
npm run build
```

### 2. Verify the Build
Check that `dist/index.html` uses relative paths:
```bash
cat dist/index.html
```

You should see:
```html
<script type="module" crossorigin src="./assets/index-*.js"></script>
<link rel="modulepreload" crossorigin href="./assets/vendor-*.js">
<link rel="stylesheet" crossorigin href="./assets/index-*.css">
```

**NOT** absolute paths like:
```html
<script type="module" crossorigin src="/assets/index-*.js"></script>
```

### 3. Upload to cPanel
Upload the entire contents of the `dist/` folder to your cPanel hosting:

**Files to upload:**
- `index.html` (main entry point)
- `assets/` (folder with all JS and CSS files)
- `logo.svg` (favicon)
- `.htaccess` (URL rewriting for client-side routing)
- All other static assets (images, PDFs, etc.)

**Upload location:**
- Domain root: `/public_html/` or `/www/`
- Subdirectory: `/public_html/breakdowns/` or similar

### 4. Verify Deployment
1. Navigate to https://breakdowns.gobarry.co.uk
2. Open browser DevTools (F12)
3. Check the Console tab - should be no 404 errors
4. Check the Network tab - all assets should load with 200 status

## Troubleshooting

### Still Getting 404 Errors?

1. **Check file permissions**
   - Files: 644 (rw-r--r--)
   - Folders: 755 (rwxr-xr-x)

2. **Verify .htaccess is uploaded**
   - Some FTP clients hide dotfiles by default
   - Enable "Show hidden files" in your FTP client

3. **Check asset paths in index.html**
   ```bash
   # Should see "./" not "/"
   grep "src=" dist/index.html
   ```

4. **Clear browser cache**
   - Hard refresh: Cmd+Shift+R (Mac) or Ctrl+Shift+R (Windows)
   - Or use incognito/private mode

5. **Check server logs**
   - cPanel > Errors log
   - Look for 404 errors and note the requested path

### Assets Load but App is Blank?

1. **Check API configuration**
   - Verify backend URL is correct: https://breakdown-guide.onrender.com
   - Check CORS is enabled on backend
   - Check Supabase credentials in environment

2. **Check Console errors**
   - Open DevTools Console
   - Look for JavaScript errors
   - Check for CORS errors

3. **Verify authentication**
   - App requires valid supervisor login
   - Test with known credentials

## Important Notes

1. **Always rebuild before deploying**
   - Old dist folder may have absolute paths
   - Run `npm run build` to generate fresh build

2. **Don't edit dist/ manually**
   - Changes will be lost on next build
   - Edit source files and rebuild

3. **Keep .htaccess**
   - Required for React Router client-side routing
   - Without it, direct URLs will 404

4. **Test in incognito mode**
   - Avoids caching issues
   - Shows what new users will see
